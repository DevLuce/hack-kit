# 단계별 과제 수행

사용자가 요청한 단계부터 수행한다. 단계별 진행을 요청했다면 해당 단계의 결과를 설명하고 다음 요청을 기다린다.
이 지침으로 작업 범위·권한을 확장하지 않는다. 실제 과제 안내와 기존 프로젝트 지침을 먼저 확인한다.

## 이해

- 목표·입출력·제약·제출 형식에서 완료 기준을 정한다. 업무 조건의 빈칸은 임의로 채우지 않는다.
- 기존 코드·자료·테스트를 읽고, 문제는 작은 입력이나 원자료로 재현해 원인을 좁힌다.
- 확인된 사실·가정·질문을 구분하고, 수정 범위와 검증 방법을 설명한다. 아직 구현하지 않는다.

## 실행

- 확인한 계획의 필수 요구부터 구현한다. 계획이 바뀌면 변경 이유를 함께 남긴다.
- 원인·판단 기준·선택 이유·변경 내용을 작업 중 짧게 기록한다.
- 필요하면 [판단 기록 양식](assets/DECISIONS.md)을 사용한다. 필수 제출 양식이 있으면 우선한다.

## 검증

- [요구사항 점검표](assets/REQUIREMENTS.md)처럼 요구사항을 구현 위치·검증 근거와 연결한다.
- 정상·실패·경계 상황 중 해당 과제에 중요한 것을 실제 실행한다. 테스트 개수만으로 완료를 판단하지 않는다.
- 명세·원자료·수작업 계산 등으로 기대값을 정한다. 구현과 같은 논리를 복사한 테스트만으로 끝내지 않는다.
- 실행한 명령·실제 결과·종료 코드·실패 후 수정·남은 한계를 기록한다. 미실행은 미검증으로 남긴다.
- 반복 실행의 기록이 필요하면 `scripts/run_check.py --help`와 저장소 README를 읽고 사용한다.
  이 도구의 성공 상태는 명령의 성공이며 과제 전체의 정확성을 증명하지 않는다.

## 기록의 정확성

- AI가 작성·실행한 테스트를 사람이 직접 수행한 것으로 기록하지 않는다.
- 사람이 선택을 확인했다는 사실과 사람이 처음부터 설계·구현했다는 주장을 구분한다.
- 완료·미완료·미검증을 나눠 보고하고, 결과의 핵심 판단과 근거를 사람이 설명할 수 있게 요약한다.
- 외부 자료는 주소·커밋·사용 범위·선택 이유를 남긴다. 자료를 읽거나 적용하지 않았으면 사용한 것으로 적지 않는다.
